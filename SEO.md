# SEO & AI answer-engine setup (EV Lineup)

How evlineup.org is made discoverable in Google/Bing **and** in AI answer
engines (ChatGPT, Claude, Gemini, Perplexity, Copilot, Grok), what is
automated, and the few steps that need the owner to sign in.

Canonical host: `https://www.evlineup.org` (always `www`, no trailing slash on
sub-pages).

---

## 1. What is in place

### Crawler-visible HTML everywhere

Most AI crawlers (GPTBot, ClaudeBot, PerplexityBot, CCBot…) do **not** run
JavaScript, and a Vite/React SPA ships an empty `<div id="root">`. Two
mechanisms give every public URL its full text in the raw HTML response, with
the same HTML served to humans and bots (no user-agent sniffing):

| URL | Mechanism |
|---|---|
| `/`, `/model_detail/:slug`, `/manufacturer/:slug`, `/compare/:pair`, `/best/:criteria` | `api/prerender.js` (Vercel function, rewritten in `vercel.json`) |
| `/what-is-ev-lineup`, `/faq`, `/alternatives`, `/vs/*` | Static HTML files in `public/`, generated by `scripts/build-pages.mjs` |

### Per-page metadata

Every public page has a unique `<title>`, a meta description, an absolute
self-referencing `<link rel="canonical">`, exactly one `<h1>`, `lang="en"`,
Open Graph tags and `twitter:card=summary_large_image`.

### JSON-LD (mirrors the visible text)

* `Organization` + `WebSite` — on every page.
* `Car` + `Offer` (real MSRP only) + `BreadcrumbList` + `FAQPage` — model pages.
* `Brand` + `ItemList` + `BreadcrumbList` — manufacturer pages.
* `ItemList` + `BreadcrumbList` + `FAQPage` — compare and best-of pages.
* `FAQPage` — `/faq` and the home-page FAQ teaser.
* `WebApplication` with a `price: "0"` offer — `/what-is-ev-lineup` (the site
  really is free; that is stated in the visible copy).
* `Article` + `BreadcrumbList` — `/alternatives` and the `/vs/*` pages.

No `aggregateRating` anywhere: there are no collected reviews, and inventing
them risks a manual action. `scripts/check-seo.mjs` fails if one appears.

### robots.txt (`public/robots.txt`)

Everything is **one group**: every `User-agent:` line is listed back-to-back,
then a single rule block (`Allow: /`, plus `Disallow:` for `/admin`,
`/auth/`, `/dashboard`, `/layout_test` and `/api/prerender`). That shape is
deliberate — a named group does *not* inherit the `*` group's rules
([spec](https://developers.google.com/crawling/docs/robots-txt/robots-txt-spec)),
so a `User-agent: Googlebot` / `Allow: /` group of its own would have handed
Googlebot the private paths. Don't put a blank line inside the group, and add
new agents above `Allow: /`, never after it.

Named agents: OAI-SearchBot, ChatGPT-User, GPTBot, Claude-SearchBot,
Claude-User, ClaudeBot, PerplexityBot, Perplexity-User, Googlebot,
Google-Extended, bingbot, Applebot, Applebot-Extended, DuckAssistBot,
DuckDuckBot, meta-externalagent, CCBot, Amazonbot, YandexBot, Bytespider,
Omgilibot, cohere-ai, anthropic-ai. Grok has no documented token, so the `*`
entry covers it.

`scripts/check-seo.mjs` parses robots.txt into groups and evaluates the
**effective** verdict (most specific matching group, then longest-match rule)
for every named agent, for `*`, and for an unlisted bot — so a future named
group that accidentally drops the exclusions fails the check.

Training crawlers are allowed on purpose: being in the models is how people
end up being told about EV Lineup when they ask an assistant about EVs.

### sitemap.xml

`/sitemap.xml` is served by `api/sitemap.js`, which fetches the backend's
data-driven sitemap (every model, manufacturer, comparison and best-of URL,
generated from the database) and merges in the frontend-only marketing URLs
listed in `STATIC_URLS`. If the backend is unreachable it still returns a
valid sitemap of the static URLs. `Content-Type: application/xml`.

Two rules for `STATIC_URLS`:

* **Only self-canonical URLs.** `/about`, `/advertise`, `/privacy` and
  `/terms` are React-only routes served from `app.html`, whose canonical is
  `/`; submitting them would submit non-self-canonical pages, so they are left
  out until they have their own crawler-visible content and metadata (see
  *Known gaps*). They are still crawlable — just not advertised.
* **`lastmod` is a real date or absent.** The marketing pages carry
  `CONTENT_UPDATED` (the date their content was last edited, matching the
  visible "Last updated" line). The data-driven routes (`/` and the best-of
  lists) change whenever the database does, with no date to point at, so they
  ship no `lastmod` at all. Never stamp `new Date()` — a sitemap that claims
  every page changed today teaches crawlers to ignore the field.

### llms.txt / llms-full.txt

`public/llms.txt` is a short, factual index (what the site is, who it is for,
key pages with absolute URLs, URL patterns, the public API). `public/llms-full.txt`
is the complete plain text of the static public pages, generated from the same
source as the HTML, so the two can't drift. Both are real files, so they are
served as `text/plain` — not as the SPA shell with a 200, which is worse than a
404. Note: large studies show no measurable citation benefit from these files;
they are cheap and accurate, and that is the whole justification.

### Performance basics

The marketing pages are single static HTML files with inlined CSS (~4 kB), no
JavaScript, no web fonts and one image that carries explicit `width`/`height`
plus `loading="lazy"` and `decoding="async"` below the fold.

## 2. Owner steps (require signing in — not done here)

1. **Google Search Console** — <https://search.google.com/search-console>
   * Preferred: add a **domain property** `evlineup.org` and verify with the
     DNS TXT record Google gives you (covers www and non-www, http and https).
   * Alternative without DNS access: add the URL-prefix property
     `https://www.evlineup.org/`, choose "HTML tag", and paste the
     `<meta name="google-site-verification" content="…">` into `index.html`
     inside the `<!-- meta:start -->` block **and** into the `layout()` head in
     `scripts/build-pages.mjs` (then `npm run seo:pages`), so both the SPA
     shell and the static pages carry it.
   * Submit `https://www.evlineup.org/sitemap.xml`.
   * Check **Settings → Search generative AI** is left on "include", and watch
     the Generative AI performance report.
2. **Bing Webmaster Tools** — <https://www.bing.com/webmasters>. Use "Import
   from Google Search Console" (fastest), or verify with the same DNS TXT /
   meta-tag approach. Bing feeds Copilot, DuckDuckGo and part of ChatGPT
   search, so this matters as much as Google.
3. **IndexNow** — nothing to sign into; the key file is already deployed (see
   below). Bing/Yandex/Seznam/Naver pick it up automatically.
4. Optional: add `sameAs` links (X, GitHub) to the `Organization` JSON-LD in
   `api/_seo.js` and `scripts/build-pages.mjs` once those profiles exist. They
   were left out rather than guessed.

**Do not** add a verification token until you own the matching property —
a placeholder token is worse than none.

```bash
npm run seo:indexnow -- --dry-run     # print the payload, send nothing
```

rotate by renaming the file in `public/` and updating the default in
`scripts/indexnow.mjs`. Google ignores IndexNow; it uses the sitemap.

## 4. How prerendering works

```
request /  ──► vercel.json rewrite ──► /api/prerender?page=home
                                            │
                      fetch https://<host>/app.html  (the SPA shell)
                      fetch https://ev-backend-three.vercel.app/...  (data)
                                            │
          replace <!-- meta:start … meta:end --> with per-page head tags
          replace <div id="root"></div> with
              <div id="root">…page content…</div>
              <div id="seo-content">…prose, FAQ, internal links…</div>
                                            │
                      200 text/html, s-maxage=3600
```

* `npm run build` renames `dist/index.html` to `dist/app.html` so the
  filesystem never beats the `/` rewrite.
* **Two blocks, on purpose.** `#root` is the page content React replaces when
  it mounts (`createRoot` clears `#root`'s children). `#seo-content` is a
  *sibling* of `#root`, so the prose sections, the home-page FAQ and the
  internal-link block stay on the page for readers as well as crawlers. React
  cannot touch it. Anything whose JSON-LD claims it is visible — the home
  `FAQPage` especially — belongs in the tail, not in `#root`.
  `scripts/check-seo.mjs` asserts the tail is outside `#root` and still holds
  100+ words of text.
* The function **fails open**: any error serves the untouched shell, and an
  unknown model/make/compare/best slug returns 404.
* `api/_seo.js` holds the shared pieces: site-wide JSON-LD, breadcrumbs, the
  internal-link block, the home-page prose sections, and the intro paragraphs
  for manufacturer/compare/best pages. Every value that comes from the
  database goes through `esc()` (HTML), `num()` (numeric spec fields, so a
  non-numeric value is dropped instead of printed) or `safeUrl()` (http/https
  only — a `javascript:` website_url is suppressed). JSON-LD is emitted by
  `jsonLdScript()`, which escapes `<`, `>` and `&` as `\u00xx`, so a record
  containing `</script>` can't break out of the block.
* Static pages are plain files, so they do not depend on the backend at all.

Render them locally (needs network: live API + live shell):

```bash
npm run seo:render                                   # -> dist/__preview/*.html
node scripts/render-prerender.mjs --page best --slug electric-trucks
```

## 5. Adding a new page

### A static marketing page (preferred for evergreen content)

1. Add the copy to `scripts/seo-content.mjs` (that file is the single source of
   truth; keep every claim checkable).
2. Add a `…Page()` builder plus an entry in `renderAll()` in
   `scripts/build-pages.mjs`.
3. `npm run seo:pages` — writes `public/<slug>.html`, `llms.txt`,
   `llms-full.txt`.
4. Add a `vercel.json` rewrite `"/<slug>" → "/<slug>.html"` **before** the
   `"/(.*)"` catch-all, and a trailing-slash redirect.
5. Add the URL to `STATIC_URLS` in `api/sitemap.js`, to `STATIC_PAGES` in
   `scripts/check-seo.mjs`, to `DEFAULT_PATHS` in `scripts/indexnow.mjs`, and
   to the footer (`scripts/build-pages.mjs` `footer()` + `src/components/Footer.tsx`).
6. `npm run build && npm run seo:check`.

### A new prerendered route type

1. Add a builder in `api/prerender.js` returning `{ meta, content, tail }`
   (use `metaBlock()`; `tail` is normally `linksBlock()`), and dispatch it in
   `handler`. Escape every database value — see section 4.
2. Add the `vercel.json` rewrite, and a React route in `src/components/App.tsx`
   so humans get a real page after hydration.
3. Extend `DEFAULT_TARGETS` in `scripts/render-prerender.mjs` so the checker
   covers it.

Keep JSON-LD a mirror of what is visible, and keep prices/counts derived from
the live data rather than typed in.

## 6. Verification

```bash
npm ci
npm run build          # tsc + vite build (must pass)
npm run seo:check      # 353 assertions; --no-live to skip the network ones
```

`scripts/check-seo.mjs` reads the built `dist/` output and asserts, for every
public page: unique title (≤75 chars), unique meta description (80–230 chars),
absolute self-referencing canonical, exactly one `<h1>`, `lang`, OG and Twitter
tags, JSON-LD that parses and contains `Organization` + `WebSite`, no
`aggregateRating`, and more than 300 crawler-visible words with JS stripped.
It also checks the effective robots.txt rules per bot, the llms files, the
IndexNow key file, the `vercel.json` rewrite order, the sitemap URL list and
`lastmod` policy, and that hostile database values (markup, `javascript:`
URLs, non-numeric specs) come out of `api/_seo.js` as escaped text. Then it
renders the five prerendered route types against the live API, applies the
same per-page checks, and asserts the `#seo-content` tail is a sibling of
`#root`.

## 7. Content rules used here

* **Truthful only.** Model counts, brand counts, prices and ranges come from
  the live database (87 models / 32 brands with models / 35 manufacturer
  profiles on 2026-10-21) or are generated at request time. Superlatives that
  could not be checked ("the most complete database", "37 manufacturers", "all
  data verified") were removed from the home page and the SPA shell meta.
* **Competitor pages are fair and dated.** `/vs/*` and `/alternatives` only
  state general, well-known facts about Edmunds, Kelley Blue Book, Car and
  Driver and fueleconomy.gov, hedged with "as of October 2026, per its
  website", link to the competitor, and each page says where the competitor is
  stronger. They carry a visible "Last updated" date — keep it true when you
  edit them.
* **One page per real intent**, not per keyword variant (Google calls the
  latter scaled content abuse).

## 8. Known gaps

* `/about` (the React `AboutPage`) is still SPA-only: a JS-less crawler sees
  an empty shell there, and `app.html` canonicalises it to `/`, so it is
  **not** in the sitemap. It was left alone deliberately
  — PR #8 edits that component, and its visible stat cards ("400+ Electric
  Vehicles", "30+ Manufacturers") do not match the database (87 models, 32
  brands with models, 35 manufacturer profiles), so they should be corrected
  before the page is prerendered. `/what-is-ev-lineup` carries the accurate
  explainer content in the meantime.
* `/advertise`, `/privacy` and `/terms` are SPA-only for the same reason and
  are also out of the sitemap. Giving them a prerendered route (or static
  files) with their own title/description/canonical is the fix.
* `/people`, `/marketplace` and `/news` are also SPA-only. `/marketplace` is a
  coming-soon page, so there is nothing to prerender yet.
* The signed-in dashboard's features (favorites, garage, notes, saved
  comparisons) are marked "coming soon" in `src/pages/DashboardPage.tsx`. The
  FAQ says exactly that — if they ship, update the "Is EV Lineup free, and do
  I need an account?" answer in `scripts/seo-content.mjs` and re-run
  `npm run seo:pages`.
* The hero image on prerendered model pages has no `width`/`height` because
  the intrinsic size is not in the API response.

## 9. Off-site (the biggest remaining lever)

Rankings and AI citations both lean heavily on being mentioned elsewhere.
Worth doing, none of it in this repo: EV subreddits and forums where a spec
comparison genuinely answers the question, Wikipedia-style external-link
sections where appropriate, directory and "best EV sites" listings, and X
posts (Grok searches X directly). A monthly prompt check in ChatGPT, Claude,
Perplexity, Gemini and Grok ("best EV comparison site", "EV Lineup vs
Edmunds", "cheapest electric car") is the cheapest way to see whether any of
this is working.
